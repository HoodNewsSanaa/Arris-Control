Android 0.4.5 simplifies existing local admin login: enter the router address, username and admin password. Serial and certificate MAC are learned automatically from the local certificate and authenticated API, then the verified login is saved using Android Keystore.

Every verified router keeps its own encrypted login. Opening the app or changing Wi-Fi checks saved addresses and local gateways in the background, matches the router's pinned certificate, and uses the matching saved login. This also works when two networks use the same IP address. If several saved routers are present, the last selected router is preferred; otherwise choose one under Connections. Automatic matching can be disabled on the connection screen. Full subnet scans remain manual; changed bridge-mode addresses may require Find ARRIS routers once.

WOBA now offers **Manage settings — keep WOBA active**. It reuses the verified saved admin login, or reviews establishing and remembering a generated local admin password through WOBA. This opens the full settings interface without completing onboarding or contacting ARRIS. The firmware's direct WOBA API has fewer operations; full settings use normal local admin authentication. The WOBA HTTP session is retained between inspection, review and application instead of opening competing sessions.

This release retains the previous onboarding and mesh features. Checks cover local identity discovery without serial/MAC input, incorrect credentials, missing identity, invalid routing mode, and credential matching across networks with identical addresses. Native Android HTTPS/Keystore/update checks run in the release workflow.

Previous release details:

Android 0.4.4 removes the phone-Bluetooth requirement from onboarding completion. The Overview and WOBA screens open a local completion/status screen using the saved normal admin login. Fresh login responses show the completion flag and whether the router's onboarding process is running; that process status does not establish whether the router is advertising over Bluetooth.

On the inspected W30 hardware/firmware, the app can review one fixed completion request through the normal local API when the onboarding process is present and startup/update activity is inactive. It rechecks identity, certificate pin, mode and process state after review. A fresh normal login must report OBASTATUS=0 before completion is verified. An acknowledgement alone is not success, and an uncertain request is never automatically repeated. If the process is stopped, the app explains that the known completion path is unavailable; normal settings and mesh inspection remain usable. Other firmware completion handlers remain unverified and are not used as automatic fallbacks. Physical-router validation is still outstanding.

Satellite setup keeps the controller connected over Wi-Fi/Ethernet and uses phone Bluetooth only to inspect the new satellite. The selected identity is retained while opening the controller discovery window and checking fresh topology. A stopped controller Bluetooth process or incomplete onboarding flag does not block these inspection/discovery tools. The app reports a verified join only with a matching router node in the controller network map plus a matching active backhaul association. Discovery entries, client nodes, stale snapshots and acknowledgements do not count as joined satellites. Wired backhaul lacking active-link evidence remains unverified.

Saved normal admin logins remain the ongoing access path. WOBA is labelled as initial admin setup/recovery. Full offline satellite provisioning remains unverified: this build improves discovery and join verification, but does not guess cloud, backhaul-password or satellite-provisioning writes. The cause of Bluetooth read code 115 remains unresolved.

Release checks include exact completion payloads, stopped/unknown process and update guards, identity/pin changes, uncertain writes, false-success refusal, satellite correlation and continued normal bridge-mode administration after simulated onboarding completion. Android TLS/Keystore/update tests run on the installed APK in the release workflow.
